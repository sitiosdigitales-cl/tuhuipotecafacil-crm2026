# BUG-119 · El contador de login pierde incrementos simultáneos

Severidad: alto
Archivo: `src/app/api/auth/login/route.ts`
Pruebas: `tests/auth/login-attempt-persistence.test.ts`, `tests/db/atomic-login-migration.test.ts`

## Cómo reproducirlo

Dos solicitudes incorrectas pueden leer el mismo valor de `intentosfallidos` y
guardar después el mismo incremento. El contador final no representa todos los
intentos procesados.

## Qué debería pasar

Cada intento debe bloquear y actualizar una sola fila dentro de la misma
transacción. Una cuenta cuyo bloqueo ya venció debe comenzar nuevamente desde
un intento, no quedar bloqueada de inmediato.

## Corrección

Mover el incremento a una función PostgreSQL atómica, sin ejecución para roles
públicos, y hacer que el endpoint use esa operación en lugar de calcular el
valor en memoria.
