# BUG-089 · La solicitud de documentos entregaba enlaces inutilizables

Severidad: alta
Archivo: src/componentes/documentos/SolicitarDocumentos.tsx
Prueba: tests/business/document-request-link.test.ts

## Cómo reproducirlo
Generar el enlace desde la ventana de solicitar documentos. La interfaz
construía una ruta `/subir-documentos` que no existe, incluía el identificador
del lead, la lista de documentos y un token aleatorio que ninguna ruta
comprobaba. El correo, al ejecutarse en servidor, apuntaba a
`http://localhost:3000/portal-cliente?lead=...`.

## Qué debería pasar
Todos los canales deben dirigir al portal autenticado, que resuelve al cliente
por su sesión. La URL no necesita ni debe transportar el identificador del lead
o su documentación. La interfaz solo debe confirmar un correo cuando la API
confirma la entrega, y no llamar "enviado" a un borrador de WhatsApp.

## Corrección aplicada
El enlace apunta únicamente a `/portal-cliente`. Los correos resuelven una URL
HTTPS desde `APP_URL`, `NEXT_PUBLIC_APP_URL` o la variable automática
`VERCEL_PROJECT_PRODUCTION_URL`; en producción una configuración ausente falla
en vez de usar localhost. WhatsApp incorpora el portal y la lista solicitada,
y el correo conserva los errores de la API.

Referencia: [variables de sistema de Vercel](https://vercel.com/docs/environment-variables/system-environment-variables).

## Acción operativa pendiente
Cada cliente que use el portal debe tener una cuenta `CLIENTE` vinculada al
mismo email de su lead. Crear o invitar esas cuentas es una operación de
negocio; el enlace ya no trata el RUT ni un token aleatorio como credencial.
