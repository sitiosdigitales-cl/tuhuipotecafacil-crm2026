# BUG-094 · La administración aceptaba cuentas con datos inválidos

Severidad: crítico  
Archivos: `src/app/api/usuarios/route.ts`, `src/app/api/usuarios/[id]/route.ts`  
Prueba: `tests/api/usuarios-write-validation.test.ts`

## Cómo reproducirlo

Enviar desde una sesión `SUPER_ADMIN` una creación o edición con una contraseña
de seis caracteres, un rol que no existe, un estado desconocido o un cuerpo
arbitrariamente grande. La API confiaba en el objeto recibido y lo enviaba a la
base de datos.

## Qué debería pasar

La API debe ser la fuente de verdad: aceptar solo JSON acotado, validar campos y
catálogos, y exigir al menos 15 caracteres mientras el sistema no tenga MFA.
La interfaz debe comunicar exactamente la misma política. El mínimo sigue la
[guía vigente de NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html#passwordver)
y la [guía de autenticación de OWASP](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html#implement-proper-password-strength-controls).
