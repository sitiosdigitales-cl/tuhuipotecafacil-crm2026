# BUG-101 · Un SUPER_ADMIN podía eliminar su propia vía de acceso

Severidad: crítico  
Archivos: `src/app/api/usuarios/[id]/route.ts`, `src/app/(dashboard)/usuarios/page.tsx`  
Prueba: `tests/api/usuarios-write-validation.test.ts`

## Cómo reproducirlo

Con una sesión `SUPER_ADMIN`, editar el mismo usuario para asignarle otro rol o
un estado no activo, o llamar a `DELETE /api/usuarios/<id-propio>`. La API
ejecutaba el cambio y podía dejar al equipo sin la cuenta con la que estaba
administrando el sistema.

## Qué debería pasar

Una cuenta administradora no debe poder degradarse, inhabilitarse ni eliminarse
a sí misma. Esas operaciones deben realizarse desde otra cuenta `SUPER_ADMIN`.
La interfaz debe ocultar esas acciones para la cuenta actual y la API debe
rechazarlas aunque se invoque directamente.
