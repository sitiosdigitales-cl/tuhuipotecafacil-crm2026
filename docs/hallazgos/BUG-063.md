# BUG-063 · La sesión expone el token y permanece vigente 24 horas

Severidad: alta
Archivo: src/app/api/auth/login/route.ts; src/app/api/auth/me/route.ts; src/lib/jwt.ts
Prueba: tests/auth/session-cookie-lifecycle.test.ts

## Cómo reproducirlo

Un login correcto devuelve el JWT dentro del JSON, además de escribirlo en dos
cookies. Ambas duran 24 horas y `/api/auth/me` valida la cuenta, pero no renueva
una sesión más corta. Por eso una sesión copiada desde el JavaScript o una
cuenta deshabilitada conserva una ventana amplia antes de expirar.

## Qué debería pasar

El token debe existir solo en una cookie `httpOnly`, emitida por 30 minutos. La
comprobación periódica de `/api/auth/me` debe validar estado y rol contra la base
antes de renovar esa cookie. La cookie antigua solo se acepta para migración y
deja de emitirse en sesiones nuevas.
