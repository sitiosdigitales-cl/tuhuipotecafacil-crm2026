# BUG-133 · Un mensaje rechazado podía quedar como enviado

Severidad: alta
Archivo: `src/lib/hooks/useChat.ts`
Prueba: `tests/state/chat-mutation-persistence.test.tsx`

## Comportamiento observado

El chat agregaba un mensaje temporal con estado `ENVIADO` antes del POST. Si la
API respondía 4xx/5xx con JSON, no entraba al `catch` y ese mensaje permanecía
visible. Eliminar y reaccionar también cambiaban el estado local antes de la
respuesta y silenciaban cualquier fallo.

## Comportamiento esperado

Enviar, eliminar y reaccionar deben modificar la conversación solo con el
objeto confirmado por el servidor. Si una operación falla, el mensaje previo y
el texto que la persona estaba escribiendo deben conservarse y la interfaz debe
informar el resultado.

## Impacto

Una conversación podía mostrar como enviado o eliminado algo que no existía en
la base. Al recargar, el historial cambiaba y se perdía el texto no entregado.

## Corrección

Las tres mutaciones esperan `response.ok`, `success` y `data`, normalizan el
registro persistido y propagan el fallo. El input se limpia solo con confirmación
y la vista muestra mensajes de error específicos.
