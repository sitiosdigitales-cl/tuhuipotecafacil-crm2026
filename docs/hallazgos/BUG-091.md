# BUG-091 · El seed inicial creaba cuentas que no podían iniciar sesión

Severidad: alta
Archivo: prisma/seed-usuarios.sql
Prueba: tests/auth/admin-bootstrap.test.ts

## Cómo reproducirlo
Ejecutar el seed y tratar de entrar con la contraseña que el propio archivo
documentaba. `bcrypt.compare("admin123", hash)` devuelve `false`; una cadena
tenía 59 caracteres y el comentario de referencia solo 29. El seed también
insertaba `GERENTE`, rol que ya no existe en la aplicación.

## Qué debería pasar
El repositorio no debe crear cuentas con contraseñas conocidas ni prometer
credenciales que no funcionan. La recuperación inicial debe exigir una
contraseña fuerte entregada fuera del código y usar la service role únicamente
desde una herramienta local explícita.

## Corrección aplicada
El seed dejó de insertar usuarios. `scripts/bootstrap-admin.mjs` crea o recupera
una cuenta `SUPER_ADMIN` con bcrypt costo 12, activa la cuenta y limpia el
bloqueo solo cuando recibe URL, service role, identidad, contraseña y
`BOOTSTRAP_CONFIRM=RESET_SUPER_ADMIN`. No existe endpoint HTTP ni valor por
defecto. El procedimiento está en `docs/recuperar-acceso-admin.md`.

## Acción operativa pendiente
Una persona autorizada debe ejecutar el procedimiento contra el proyecto
correcto y verificar el login en una ventana privada. Codex no usa la service
role ni modifica cuentas reales.
