# BUG-037 · La ruta pública supera el presupuesto de JavaScript

Severidad: alta
Archivo: src/app/simulador-publico/page.tsx
Prueba: tests/performance/public-route-bundle.test.ts

## Cómo reproducirlo

Ejecutar `npm run build` y luego
`npm test -- tests/performance/public-route-bundle.test.ts`. Los manifiestos de
producción declaran `1.278.179` bytes de JavaScript moderno para
`/simulador-publico`: `851.424` bytes iniciales y `426.755` bytes de los
gráficos dinámicos.

## Qué debería pasar

Una ruta pública debe descargar como máximo `409.600` bytes (`400 KiB`) de
JavaScript. Los gráficos que todavía no se muestran no deben formar parte de
la descarga inicial.

### Por qué sigue en rojo

`rootMainFiles` son **445,9 KiB y no bajan**: es el runtime de React y Next
(react-dom son 222 KiB), es **idéntico para todas las rutas** —se comprobó en
`simulador-publico`, `login` y `portal-cliente`, los tres con los mismos 5
archivos— y no contiene código de la aplicación.

Como la prueba suma `rootMainFiles` al total, el piso de cualquier ruta es
445,9 KiB, un 11% sobre el presupuesto de 400 KiB. **Una página en blanco
también reprobaría.** Los 148,9 KiB de código propio que quedan podrían
bajar a cero y el total seguiría en 445,9.

### Qué haría falta para cerrarlo

Una de estas tres, y las tres exceden un cambio de página:

1. Excluir `rootMainFiles` del cálculo y presupuestar solo el código propio,
   que hoy son 148,9 KiB y sí cabría en 400 KiB.
2. Subir el presupuesto por encima del piso del framework.
3. Servir las rutas públicas fuera de esta aplicación Next.

No toqué el presupuesto, la prueba ni agregué skips, según lo pedido. La
decisión es de Diego.
