# BUG-127 · Integraciones confirmaba conexiones y secretos no persistidos

Severidad: alta
Archivo: `src/app/(dashboard)/integraciones/page.tsx`
Prueba: `tests/ui/integrations-persisted-inventory.test.ts`

## Comportamiento observado

La pantalla declaraba trece servicios con estados escritos en el código,
incluido un identificador duplicado. Conectar, desconectar, guardar API keys y
generar una llave solo cambiaba estado local o cerraba un modal con un mensaje
de éxito. El configurador WordPress también permitía crear registros de prueba
desde una pantalla operativa.

## Comportamiento esperado

El inventario debe reflejar únicamente filas persistidas y no debe solicitar
credenciales hasta que exista un flujo de servidor específico, validado y
auditable. Las comprobaciones de proveedores deben ejecutarse en staging con
datos sintéticos, no crear datos de prueba desde producción.

## Impacto

Una persona podía creer que un proveedor estaba activo, que sus secretos habían
quedado almacenados o que una desconexión era efectiva cuando todo desaparecía
al recargar. También podía incorporar datos de prueba a la cartera real.

## Corrección

La página ahora consulta `GET /api/integraciones`, muestra solo campos
persistidos y queda expresamente en modo de solo lectura. Se retiraron el
catálogo local, los estados manuales, los formularios de secretos, el generador
de llaves y el configurador que creaba leads de prueba.
