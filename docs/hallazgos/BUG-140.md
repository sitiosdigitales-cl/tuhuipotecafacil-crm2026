# BUG-140 · El piping pierde correos Latin-1 con caracteres acentuados

Severidad: alta
Archivo: `wordpress/email-handler.php:64`
Prueba: `tests/wordpress/email-handler-latin1.test.ts`

## Cómo reproducirlo

Entregar al handler un mensaje MIME `text/plain` declarado como
`ISO-8859-1`, cuyo cuerpo incluya caracteres fuera de ASCII, por ejemplo
`Crédito para José Peña en Ñuñoa`.

El handler termina correctamente y registra una respuesta satisfactoria si el
destino responde `204`, pero el cuerpo HTTP que recibe el webhook tiene cero
bytes. `json_encode` devuelve `false` ante los bytes Latin-1 y ese resultado se
entrega directamente a cURL.

## Qué debería pasar

El handler debe convertir cada parte MIME desde su charset declarado a UTF-8,
serializar un JSON válido y conservar intactos los caracteres del mensaje. La
serialización también debe tener una degradación segura si el charset falta o
es incorrecto.

## Impacto

El CRM no crea el lead y no conserva el contenido necesario para recuperarlo.
Como el proceso puede recibir una respuesta HTTP satisfactoria aun enviando el
cuerpo vacío, el fallo tampoco queda representado correctamente por su código
de salida.
