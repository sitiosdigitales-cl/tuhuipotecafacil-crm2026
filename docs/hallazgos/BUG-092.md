# BUG-092 · El login ocultaba la causa real del rechazo y enviaba al rol equivocado

Severidad: media
Archivo: src/lib/contexts/AuthContext.tsx
Prueba: tests/auth/login-feedback.test.tsx

## Cómo reproducirlo
Intentar entrar con una cuenta temporalmente bloqueada, inactiva o durante un
fallo del servidor. Aunque la API respondía con la causa correspondiente, la
interfaz siempre mostraba "Credenciales incorrectas". Un `CLIENTE` o `AGENTE`
que lograba entrar era enviado primero a `/dashboard`, ruta que no corresponde
a esos roles.

## Qué debería pasar
La pantalla debe conservar los mensajes controlados de la API y distinguirlos
de un fallo de red. Después del éxito debe navegar directamente al inicio del
rol. Los labels deben estar asociados a sus controles para que teclado,
autocompletado y tecnologías de asistencia identifiquen el formulario.

## Corrección aplicada
El contexto devuelve un resultado tipado con usuario o mensaje. `CLIENTE` va a
`/portal-cliente`, `AGENTE` a `/documentos` y el equipo comercial a
`/dashboard`. Se añadieron ids, `htmlFor`, autocomplete y nombre accesible al
control que muestra la contraseña.
