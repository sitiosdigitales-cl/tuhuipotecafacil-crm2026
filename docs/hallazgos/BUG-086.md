# BUG-086 · Los códigos de referido no tenían propietario comprobable

Severidad: alta
Archivo: src/app/api/referidos/validar/route.ts
Prueba: tests/api/referral-code-validation.test.ts

## Cómo reproducirlo
Consultar la validación con cualquier texto que cumpliera el patrón
`REF-XXX-XXXXXX` devolvía `valido: true`. El registro aceptaba ese mismo texto,
creaba un lead y no guardaba qué usuario había originado el referido. Además,
el panel generaba códigos aleatorios en `localStorage`, distintos por navegador.

## Qué debería pasar
El código debe ser emitido por el servidor, tener una firma comprobable,
corresponder a un usuario activo y volver a validarse al registrar el lead. El
panel debe obtener siempre el mismo código desde una ruta con sesión.

## Corrección aplicada
Se incorporó un código determinista firmado con HMAC y separación de dominio,
una ruta autenticada para obtenerlo y una resolución contra usuarios activos.
El registro guarda el identificador y nombre del propietario comprobado, y ya
no expone la ficha completa del lead en su respuesta.
