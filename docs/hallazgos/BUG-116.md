# BUG-116 · El editor de permisos confirmaba cambios que no se aplicaban

Severidad: crítica
Archivo: src/app/(dashboard)/permisos/page.tsx
Prueba: tests/ui/permissions-read-only.test.ts

## Cómo reproducirlo

Entrar a Permisos, cambiar cualquier capacidad de un rol y pulsar Guardar
Cambios. La pantalla esperaba un segundo y mostraba Guardado, pero no llamaba a
una API, no persistía la matriz y no cambiaba las comprobaciones del proxy ni de
los endpoints.

## Qué debería pasar

Una pantalla administrativa no debe afirmar que cambió el control de acceso si
las reglas reales siguen iguales. Mientras no exista una única matriz dinámica,
el catálogo debe ser de solo lectura y explicar dónde se asignan los roles que
sí están soportados.

## Corrección aplicada

Se retiró el editor local y su confirmación simulada. La página ahora deriva los
cinco roles de `ROLES_CONFIG`, explica que las capacidades se validan en código
y enlaza a Usuarios para asignar un rol mediante la API existente.
