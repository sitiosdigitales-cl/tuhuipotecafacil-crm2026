# BUG-058 · Solicitudes aceptan estado e identificadores controlados

Severidad: crítica
Archivo: src/app/api/solicitudes/route.ts:86-104; src/app/api/solicitudes/[id]/route.ts:65-88
Prueba: tests/business/solicitud-controlled-fields.test.ts

## Cómo reproducirlo

Crear una solicitud enviando `estado: "APROBADO"`, o editarla enviando campos
como `estado`, `bancoAsignado`, `id` y `leadId`. La creación copia el estado del
cuerpo y la edición convierte cualquier clave desconocida a minúsculas, por lo
que roles operativos pueden cambiar decisiones administrativas o intentar
reemplazar identificadores. Además, el catálogo escribe `EN_REVISON` mientras
la API usa `EN_REVISION`.

## Qué debería pasar

Toda solicitud nueva debe iniciar en `EN_REVISION`. La edición debe usar una
lista cerrada: campos operativos para roles con permiso `editar`, campos de
estado/asignación solo para administración, y nunca IDs enviados en el cuerpo.
El catálogo debe usar el mismo estado canónico.
